# Prompt Recipes

These are optional starting prompts. The Snippetz UI Design skill should already activate for relevant work; these prompts help users specify scope and intent.

## Build a new product

“Use the Snippetz Labs design philosophy to build [product]. The main users are [audience], and their primary task is [task]. Use [Obsidian/Botanical/Atmospheric/your recommended skin]. Build the essential routes and interactions, make it responsive, and use realistic clearly labelled sample data only where necessary.”

## Redesign an existing application

“Inspect the existing project before changing it. Apply the Snippetz Labs design DNA to [routes/areas]. Preserve the stack, working features, data contracts, and existing behavior. Improve hierarchy, typography, spacing, layout, and responsive states. Implement the changes and run the relevant checks.”

## Translate visual references

“Study the attached references and extract their visual principles—composition, typography, color, density, surfaces, charts, and visual storytelling. Do not copy them literally. Adapt the strongest principles to [product] and implement a cohesive, production-ready interface.”

## Upgrade a dashboard

“Redesign this dashboard around decisions users need to make. Prioritize the highest-value summary, key metrics, filters, the main visualization, supporting details, and actionable alerts. Improve scanability and mobile behavior without removing useful information or inventing data.”

## Apply a consistent product skin

“Define a semantic design-token system for this product, including colors, typography, spacing, radii, borders, shadows, and motion. Apply it consistently across all relevant routes and shared components while keeping each screen suited to its task.”

## Polish a page without rebuilding it

“Keep the current information architecture and behavior. Identify and fix the most important visual issues on this page: hierarchy, spacing, alignment, readability, state design, and responsive behavior. Avoid unnecessary dependencies or unrelated refactors.”
